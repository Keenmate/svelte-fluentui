# svelte-fluentui 2.0.0-rc01 — Release Notes

**Released:** _unreleased_ · **Pre-release** (`npm install svelte-fluentui@rc`)

These notes cover the changes since **1.6.0-rc07**, the last version on npm.

This is a **major release: breaking, with no aliases.** Before the first public release the whole
API was revised for consistency: events a component defines are camelCase and take one `ctx`
object (`onFileAdd({files})`, not `onFileSelected(files)`) while lowercase `on*` props are only native
browser events, one name per concept across components (`open`, `value`, `multiple`, …), prop
values are lowercase / kebab-case, and shared logic moved into helpers. Code written for 1.x needs
updating: the old names are gone.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/KeenMate/svelte-fluentui/blob/prod/CHANGELOG.md) (section
2.0.0-rc01); this document is the upgrade guide and the highlights.

## Upgrade checklist

**Dependencies**

- [ ] Svelte `5.29.0` or newer.

**Event / callback props**

- [ ] Rename component events to camelCase and take one object — see
  [Events and callbacks](#events-and-callbacks-camelcase-one-ctx-object) for the full table.

**Prop names and values**

- [ ] Apply the [Renamed props and values](#renamed-props-and-values) table.

**Stylesheets**

- [ ] The element reset (reboot) is no longer in `svelte-fluentui/styles`. To keep the 1.x page look,
  import it once, before the main stylesheet: `import "svelte-fluentui/reboot"` (also
  `svelte-fluentui/reboot.css`). See [CSS: stylesheet clean-up](#css-stylesheet-clean-up-opt-in-reboot-one-palette-one-z-index-scale).
- [ ] Library CSS is in cascade layers. If the app loads its own reset or normalize stylesheet without a
  layer, import it into `reset` or it beats the components; drop `revert-layer` / `!important`
  workarounds aimed at the reboot. See [CSS: cascade layers](#css-cascade-layers).

**CSS custom properties**

- [ ] Custom Badge colours: `--badge-fill-<name>` / `--badge-color-<name>` → `--fluent-color-<name>` / `--fluent-color-<name>-contrast`.
- [ ] `--error` / `--warning` / `--success` / `--info` → `--fluent-color-{danger,warning,success,info}-foreground`; SCSS `$color-success|warning|error|info` → the same variables.
- [ ] Rename overridden component variables per [CSS: custom properties renamed](#css-custom-properties-renamed) (e.g. `--icon-size` → `--fluent-icon-size`, `--fluent-quickgrid-row-hover-bg` → `--fluent-quickgrid-row-bg-hover`).

**Built-in text (translations)**

- [ ] InputFile `labels`: rewrite function values as ICU strings and rename keys — see
  [Built-in text: one svelte-i18n dictionary](#built-in-text-one-svelte-i18n-dictionary).
- [ ] Replace removed props: DatePicker `openCalendarIconAriaLabel`, TimePicker `openClockIconAriaLabel`
  → `labels.openPopupAriaLabel`; Combobox `loadingText` → `labels.loading`; BadgeGroup `moreLabel` /
  `lessLabel` → `labels.showMore` / `labels.showLess`; Chip `removeLabel` → `labels.removeAriaLabel`.
- [ ] Non-English app: call `i18n.init({locale})` (or pass `culture`) — Calendar / DatePicker / QuickGrid
  `culture` now follows the i18n locale, not the browser.

**TypeScript types and exports**

- [ ] Remove imports of `Menu`, `MenuItem`, `Tree`, `TreeItem`, `ProgressBar` (empty placeholders, now gone).
- [ ] `Toast` (store type) → `ToastInstance`; `SiteSettings` (store type) → `SiteSettingsState`.

**Stores → runes services**

- [ ] `$settings.x` → `settings.x`; `$theme` / `theme.toggle()` → `settings.effectiveTheme` /
  `settings.toggleTheme()`; `navigationStore` → `navigation`; `toast.subscribe` → `toast.items` —
  see [Stores are runes services](#stores-are-runes-services).
- [ ] Remove your own `baseLayerLuminance` / `accentBaseColor` / `neutralBaseColor` code driven by
  the settings store: `settings` applies them now.
- [ ] `PositioningRegion`: drop `availableHeight` (always on) and read `--fluent-popup-available-height`
  instead of `--available-height` — see [Popups: one positioning helper](#popups-one-positioning-helper).

### Built-in text: one svelte-i18n dictionary

Every text a component renders on its own now comes from one flat dictionary run by
[svelte-i18n](https://github.com/kaisermann/svelte-i18n) (new dependency): keys
`svelteFluentUI.<component>.<key>`, English and German built in. Nothing to do for English. See
[Translations](#translations) under New API for the service and setup.

Of the 1.x API this breaks InputFile's `labels` and a few single-string props.

**InputFile `labels`**: values are ICU MessageFormat strings, not functions:

```svelte
<!-- 1.x -->
<InputFile labels={{fileCount: (n) => `${n} souborů`, maxSize: (s) => `Max. ${s}`}} />
<!-- 2.0 -->
<InputFile labels={{fileCount: "{count, plural, one {# soubor} few {# soubory} other {# souborů}}", maxSize: "Max. {size}"}} />
```

| 1.x key | 2.0 key (params) |
|---|---|
| `accepted(a)` | `accepted` (`{accept}`) |
| `maxSize(s)` / `minSize(s)` | `maxSize` / `minSize` (`{size}`) |
| `totalMaxSize(s, remaining)` | `totalMaxSize` (`{size}`), `totalMaxSizeRemaining` (`{size}`, `{remaining}`) |
| `maxFilesHint(max, remaining)` | `maxFiles` (`{max}`), `maxFilesRemaining` (`{max}`, `{remaining}`) |
| `minFilesHint(n)` | `minFiles` (`{min}`) |
| `showMore(n)` / `fileCount(n)` | `showMore` / `fileCount` (`{count}`) |
| `fileTooLarge` / `totalSizeExceeded` / `tooManyFiles` | same (`{max}`) |
| `fileTooSmall` / `tooFewFiles` | same (`{min}`) |
| `fileTypeNotAccepted(a)` | `fileTypeNotAccepted` (`{accept}`) |
| `totalProgress({…})` | `totalProgress`, `totalProgressWithFailed` (`{completed}`, `{total}`, `{failed}`, `{uploadedSize}`, `{totalSize}`) |
| `uploadedAnnouncement(n)` / `failedAnnouncement(n, e)` | same (`{name}`; `{name}`, `{error}`) |
| `emptyState` | `empty` |
| `viewFiles` | `viewFilesAriaLabel` |
| `remove` | `removeAriaLabel` + `removeTooltip` (`{item}`, the file name: "Remove report.pdf") |
| `retry` `pause` `resume` `cancel` `download` | `retryAriaLabel` … `downloadAriaLabel` |
| `browse` | `browse` (visible text), `browseAriaLabel`, `browseTooltip` |

`DEFAULT_LABELS` is gone; the English text is the exported `en` dictionary.

**Removed props** (the text is a `labels` key now):

| Component | 1.x prop | 2.0 |
|---|---|---|
| DatePicker | `openCalendarIconAriaLabel` | `labels.openPopupAriaLabel` |
| TimePicker | `openClockIconAriaLabel` | `labels.openPopupAriaLabel` |
| Combobox | `loadingText` | `labels.loading` |
| BadgeGroup | `moreLabel` / `lessLabel` | `labels.showMore` (`"+{count} more"`) / `labels.showLess` |
| Chip | `removeLabel` | `labels.removeAriaLabel` / `labels.removeTooltip` (`"Remove {item}"`) |

`placeholder`, `emptyText` and CompositeBadge `buttonTitle` stay: per-instance props still win.

### Events and callbacks: camelCase, one `ctx` object

Events a component defines are now `on` + PascalCase and receive **one object** (`ctx`), so fields can
be added later without breaking you. Lowercase `on*` props are only real browser events, forwarded
untouched (they receive the native `Event`). Functions whose return value is used are named
`…Callback` (`before…Callback` can veto, `get…Callback` extracts a value).

```svelte
<!-- 1.x -->
<Switch onchange={(checked) => save(checked)} />
<!-- 2.0 -->
<Switch onChange={({checked}) => save(checked)} />
```

| Component | 1.x | 2.0 |
|---|---|---|
| Switch | `onchange(checked)` | `onChange({checked})` |
| Slider | `onchange(value)`, `oninput(value)` | `onChange({value})`; live value via `bind:value` |
| RadioGroup | `onchange(value)` | `onChange({value})` |
| Textarea | `oninput(value)`, `onchange(value)` | `onChange({value})` on commit; `oninput` / `onchange` are now the native events |
| Accordion | `onchange(value)` | `onChange({value})` |
| AccordionItem | `onchange(ev, isExpanded)` | `onExpandedChange({expanded, sourceEvent})` |
| Checkbox | `onclick(ev, previousValue)` | `onChange({checked})` (`null` = indeterminate); `onclick` is now the native click event |
| Listbox | `onchange(ev)` | `onChange({value})` on user selection; `onchange` is the native event |
| Select | `onchange({value, selectedOption, data})` (`value` was `""` when `multiple`) | `onChange({value, option})` — `value` is the new bound value (array when `multiple`), `option` is `{value, text, data}`; no longer fires when re-picking the selected option |
| Combobox | `onchange(value)` | `onChange({value})` (always an array) |
| Combobox | `onsearch(query)` | `onSearch({term})` |
| Combobox | `filter(query, option)` | `filterCallback({term, option})` |
| TextField | `oninput`, `onchange`, `onkeydown`, `onkeyup`, `onfocus`, `onblur` (hand-forwarded) | native events and attributes (incl. `class`) forwarded via `...rest`; new `onChange({value})` on commit |
| NumberField | same hand-forwarded native events | native via `...rest`; new `onChange({value})` on commit |
| Search | `oninput(value)`, `onchange(value)` | `onSearch({term})` (debounced by `searchDelay`), `onChange({value})` on commit; `oninput`/`onchange` are native |
| Search | `focusAsync(preventScroll)` method | `focus(preventScroll)` |
| Calendar | `onDateSelected(value)` + `onDatesSelected(values)` | one `onChange({value})` (`Date` in single mode, `Date[]` in multiple/range); `value` and `selectedDates` are now bindable and updated by the calendar |
| Calendar | `onSelectionError(error)`, code `max_selectable_days_exceeded` | `onSelectionReject(ctx)`, code `max-selected-day-count-exceeded` |
| Calendar | `onPickerMonthChange(month)`, `onDayHover(date)` | `onPickerMonthChange({pickerMonth})`, `onDayHover({date})` |
| Calendar | `disabledDateFunc(date)`, `selectableDates(date)`, `highlightDates(date)`, `selectDates(date)` | `getIsDateDisabledCallback({date})`, `getIsDateSelectableCallback({date})`, `getDatesToHighlightCallback({date})`, `getDatesToSelectCallback({date})` |
| DatePicker | `onValueChange(value)`, `onOpenChange(open)`, `onPickerMonthChange(month)` | `onChange({value})`, `onOpenChange({open})`, `onPickerMonthChange({pickerMonth})` |
| DatePicker | `disabledDateFunc(date)`, `selectableDates(date)` | `getIsDateDisabledCallback({date})`, `getIsDateSelectableCallback({date})` |
| TimePicker | `onValueChange(value)`, `onOpenChange(open)`, `disabledTimeFunc(h, m, s)` | `onChange({value})`, `onOpenChange({open})`, `getIsTimeDisabledCallback({hour, minute, second})` |
| Autocomplete | `selectedOptions` (bindable) | `value` (bindable) |

`svelte/store` stores. Read their fields directly — in markup, `$derived` or `$effect` — with no `$`
prefix and no `subscribe`.

| 1.x | 2.0 |
|---|---|

### CSS: cascade layers

All library CSS now lives in cascade layers, in the order the other Keenmate libraries use
(svelte-treeview, the web components):

```css
@layer reset, variables, component, overrides;
```

| Layer | Contents |
|---|---|
| `reset` | `svelte-fluentui/reboot` |
| `variables` | design tokens: FluentUI defaults, `--fluent-*` theme variables, the `--fluent-color-*` palette |
| `component` | the global partials (layout, nav, toast, field, primitives, `<fluent-*>` fixes) and every component's own `<style>` |
| `overrides` | empty — for themes |

What changes for an app:

- **Your unlayered CSS always wins** over the library, whatever the specificity — no `!important`.
  Rules that used to lose a specificity fight against a library rule now apply.
- **An unlayered reset beats the components too** (normalize.css, Pure.css, Tailwind preflight outside
  `@layer`, `* { margin: 0 }`). Load it into `reset`:

  ```html
  <style>
  	@layer reset, variables, component, overrides;
  	@import url("…/pure-min.css") layer(reset);
  </style>
  ```

- **The library no longer overrides layered libraries.** The reboot used to beat svelte-treeview's
  checkbox (any layered rule loses to an unlayered one). Workarounds such as
  `.stv__checkbox { margin: revert-layer; border: revert-layer }` can be removed.
- **The reboot no longer draws `border: 1px solid black`** on `input`, `button`, `select`, `optgroup`
  and `textarea`. Native controls you style yourself keep your border; unstyled ones show the browser's.
- Import order of `reboot` and `styles` no longer matters.

## Behaviour changes

### Popups: one positioning helper

Every anchored popup (Select, Combobox, Autocomplete, DatePicker, TimePicker, MenuButton, ContextMenu,
the Tabs overflow menu, the AppBar "…" popover, the InputFile popover, QuickGrid menus, Tooltip) is
placed by one helper:

- **Capped to the viewport.** Each popup fits the room left between its anchor and the viewport edge
  and scrolls inside; only Select, Combobox and Autocomplete did before.
- **Same default height for the listboxes.** Select, Combobox and Autocomplete cap at `300px` by
  default (Select / Combobox used to take all the room available). Change it with `maxDropdownHeight`
  or the public `--fluent-select-dropdown-max-height` / `--fluent-combobox-dropdown-max-height` /
  `--fluent-autocomplete-dropdown-max-height`.
- **Keeps its side.** A popup opens below unless there is more room above, then stays on that side
  while the page scrolls or a filter shrinks the list. It decides again when the viewport resizes or
  it grows past the room on its side (async results).
- **Scroll closes only when the anchor moves.** Autocomplete, ContextMenu and the Tabs overflow menu
  closed on any scroll outside them; now only a scroll that moves the anchor (3px or more) closes
  them — scrolling an unrelated panel doesn't.
- **4px gap below form fields.** Select, Combobox, Autocomplete, DatePicker and TimePicker popups sit
  one `designUnit` from the field, like MenuButton (they were flush). Set
  `--fluent-popup-offset` on the field or any ancestor (`:root` for the whole app) to change the gap of
  every popup except Tooltip; `PositioningRegion` takes an `offset` prop.
- **CSS variables** on the positioned element: `--fluent-popup-available-height`,
  `--fluent-popup-available-width`, `--fluent-popup-anchor-width`. Use them to size your own content
  in a `PositioningRegion`.

### Calendar, DatePicker and QuickGrid `culture` follows the i18n locale

`culture` (month and weekday names, first day of the week, date and number formats) used to default
to `navigator.language`. It now defaults to the i18n locale (`i18n.currentLocale`) and follows
`i18n.setLocale()`, so the month names match the buttons around them. When the browser's locale is the
same language it is used instead, keeping its region (`en-GB`: Monday first; `de-AT`).

Without `i18n.init()` the locale is English, so a Czech browser now gets English month names. Set the
app's language (`i18n.init({locale: "cs"})`) or pass `culture` to keep the 1.x result.

### Small text changes

- Tabs scroll buttons: "Scroll to previous tabs" / "Scroll to next tabs" (were "left / right / up /
  down", swapped in RTL).
- Paginator: "1 item" (was "1 items"); numbers are locale-grouped ("1,234", German "1.234") and stay
  one bold run.
- InputFile remove buttons name the file ("Remove report.pdf", was "Remove file").

### MultiSplitter is content-height by default (as documented)

Leftover Blazor CSS forced `height: 100%` on every `MultiSplitter` and `overflow: hidden` on its
panes, overriding the component's own styles. With it removed, a splitter without a `height` prop
sizes to its tallest pane, and panes scroll (`overflow: auto`) instead of clipping. If a splitter
should fill a sized parent, say so:

```svelte
<div style="height: 400px">
	<MultiSplitter height="100%">…</MultiSplitter>
</div>
```

### Search ignores accents by default (`searchBehavior`)

Select type-ahead, Autocomplete's local search and the QuickGrid select / combobox / autocomplete
editors used to treat accented letters as different (`a` did not find `Ávila`); Combobox ignored
accents with no way to turn that off. All of them now take `searchBehavior`, the same option as
web-multiselect:

- `"normalized"` (default) — ignores case and diacritics: `zurich` finds `Zürich`, `sao paulo` finds `São Paulo`
- `"case-insensitive"` — ignores case only: `zürich` finds `Zürich`, `zurich` does not
- `"exact"` — case and diacritics both count

Every mode compares Unicode NFC text. It applies to the built-in matching only — `filterCallback`,
`onSearch` and `searchCallback` are untouched. To keep the old accent-sensitive matching, set
`searchBehavior="case-insensitive"` (QuickGrid: `editorOptions.searchBehavior`).
`normalizeForSearch(text, behavior)` and the `SearchBehavior` type are exported for custom matchers.

### AppBar: bar surface, active indicator, overflow

AppBar used to render only the item boxes. It now matches FluentUI Blazor's `FluentAppBar`:

- A bar surface (`--fluent-appbar-background`, default `--neutral-layer-2`) that fills its container's
  height when vertical and its width when horizontal. `orientation="horizontal"` now lays the items in
  a row (it had no layout before). Give the bar's container a height (vertical) or width (horizontal).
- `active` items show the accent indicator: start edge when vertical, bottom when horizontal.
- Items that don't fit move into a **…** popover; `showSearch` adds a search field there.
- The count badge is red (danger palette) by default, as in Blazor. To keep the 1.x accent blue:
  `--fluent-appbar-count-bg: var(--accent-fill-rest); --fluent-appbar-count-text: var(--foreground-on-accent-rest);`

### Popups close when focus moves away

DatePicker, TimePicker, MenuButton, ContextMenu, the Tabs overflow menu and the InputFile popover now
close when focus leaves the trigger and the popup (Tab-ing past them, clicking into another field),
like Select, Combobox and Autocomplete already did. Outside presses close them on `pointerdown`.
Focus moving into the popup, or a modal dialog's focus trap pulling focus back into the dialog that
owns the picker, doesn't close it.

### Accessibility: focus moves into pickers, styling hooks moved to `data-*`

- DatePicker / TimePicker opened from the keyboard (Enter / Space on the calendar / clock button,
  ArrowDown on the input) move focus into the popup; closing from inside returns focus to the
  button. Pointer opening leaves focus where it is.
- Calendar days are one tab stop (roving tabindex) instead of one per day; use the arrow keys,
  Home / End, PageUp / PageDown. Day cells are `role="gridcell"` (were `role="button"`).
- Calendar's own styling hooks moved off ARIA attributes so the ARIA can be correct:
  `.day[aria-selected]` → `[data-selected]`, `.day[aria-disabled]` → `[data-disabled]`, host
  `[aria-readonly]` → `[data-readonly]` (`aria-readonly` is now on the day grid). Update custom CSS
  that targeted the old attributes.
- Autocomplete `ariaLabel` names the search input (it was put on the root `<div>`).
- CommandPalette keeps Tab inside the palette and returns focus to the previously focused element
  on close.

### One clear (×) button: `showClear`, shown on hover or focus

Select, Combobox, Autocomplete, DatePicker and TimePicker share one clear button, modelled on
`<fluent-search>`'s: a `showClear` prop (default `true`; `showClear={false}` removes it), rendered
while there is something to clear and visible while the field is hovered or has focus. It isn't a
Tab stop and doesn't take focus; Select, DatePicker and TimePicker clear on Delete / Backspace too.

What changes for existing controls:

- Select and Combobox gain the button (they had none). Set `showClear={false}` for a value that must
  stay set.
- Autocomplete: the × no longer replaces the search icon / custom `end` — it sits before them; it
  shows in multi-select too (removes every chip) and for typed search text; its class is
  `.autocomplete-clear` (was `.clear-button`).
- DatePicker / TimePicker: the × moved before the calendar / clock icon and left the Tab order
  (Tab from the icon button now leaves the picker); Delete / Backspace on the field clears.

### CommandPalette ignores accents by default

CommandPalette takes `searchBehavior` too (default `"normalized"`): `cafe` finds `Café`, and the
highlight marks the original letters. Set `searchBehavior="case-insensitive"` for the old matching.

## New API

### Action items: one shape for every menu and toolbar

Menus, toolbars, dialog actions, palette commands and toast actions are moving to one item model
(exported from the package root): `ActionItem` / `MenuItem` / `MenuDivider` / `MenuEntry`, plus
`onAction(detail)` and `beforeActionCallback(detail)` on the component. Run order:
`beforeActionCallback` (`false` cancels) → the item's `onClick` → the built-in behaviour → `onAction`.

```ts
const items: MenuEntry[] = [
  {id: "edit", text: "Edit", icon: "edit", onClick: () => edit()},
  {divider: true},
  {id: "delete", text: "Delete", icon: "delete", isDanger: true, getIsDisabledCallback: () => !canDelete}
]
```

```svelte
<MenuButton {items} onAction={({id}) => track(id)} beforeActionCallback={({id}) => id !== "delete" || confirm("Delete?")}>
  Actions
</MenuButton>
```

Converted so far: **MenuButton**, **ContextMenu**, **Dialog** footer actions, **CommandPalette**, **Toast** links, **TopNav** items, **QuickGrid** row toolbar and context menu. Link items (`href`) can be vetoed by
`beforeActionCallback` too; the click is replayed once allowed, so your router still handles it. Static fields have a `get…Callback` twin that
wins (`getTextCallback`, `getIsDisabledCallback`, `getIsVisibleCallback`, …); `icon` takes a Fluent
icon name or a snippet; `isToggled` makes a checkable item; `shortcut` shows a key hint.

### Native attributes and events on every component

Every component that renders an element accepts its attributes and native events (`...rest`):
`aria-*`, `data-*`, `title`, `onkeydown`, … Single-element wrappers forward them to the `<fluent-*>`
element; composite components (pickers, Select, Combobox, Autocomplete, QuickGrid, Field) to their
root element. Where the component handles a native event itself (Radio `onclick`, RadioGroup / Switch
`onchange`, Slider `onchange` / `oninput`, QuickGrid `onfocusout`), your handler runs as well.

### Translations

Built-in text lives in one flat svelte-i18n dictionary (`svelteFluentUI.<component>.<key>`, English
and German built in), easy to keep in a JSON file or a database table. The service is the same as
svelte-pure-admin's:

```ts
// src/routes/+layout.svelte
import {i18n} from "svelte-fluentui"

i18n.init({
	locale: "de",
	translations: {de: {"app.title": "Übersicht", "svelteFluentUI.dialog.closeAriaLabel": "Fenster schließen"}},
	loadTranslations: async (locale) => (await fetch(`/locales/${locale}.json`)).json()
})

await i18n.setLocale("en") // switches open components
```

- `i18n`: `init`, `setLocale`, `addTranslations`, `setTranslationLoader`, `currentLocale` (reactive),
  `languages`, `isLoading`, `addLanguage` / `removeLanguage` / `setLanguages` / `getLanguage`.
- `_`, `locale`, `locales`, `isLoading`, `addMessages`, `init`, `getLocaleFrom*` re-exported from
  svelte-i18n; your app's own keys share the dictionary and the locale.
- Keys end in what they render: none = visible text, `Placeholder`, `Tooltip`, `AriaLabel`, so a
  button's caption, tooltip and screen-reader name can differ.
- Values are ICU MessageFormat: `"Page {page} of {pageCount}"`, `"{count, plural, one {# file} other {# files}}"`.
- `en` and `de` are exported (a starting file for another language); *Guides → Translations* lists every key.

**One instance:** Alert, Autocomplete, BadgeGroup, Calendar, Chip, Combobox, CommandPalette,
CompositeBadge, DatePicker (also the popup Calendar's keys), Dialog, InputFile, Paginator, Panel,
QuickGrid, Select, SiteSettings, Tabs, TimePicker, Toast, ToastContainer and TopNav take `labels`
(`XLabels`: the component's keys without the prefix, same ICU syntax), which wins over the
dictionary for that instance:

```svelte
<Paginator lastPageIndex={9} labels={{pageInfo: "Strana {page} z {pageCount}"}} />
```

### QuickGrid: virtualised rows

```svelte
<QuickGrid items={orders} {columns} virtualize sortMode="single" filterable
	style="--fluent-quickgrid-virtual-max-height: 600px" />
```

`virtualize` renders only the rows in view (plus `overscanCount`, default 5, above and below) inside a
scrolling container with a sticky header — like ASP.NET QuickGrid's `Virtualize`. Rows should be one
line of text: `itemSize` (default 37px) is their height, and the real row pitch is measured. Sorting,
filtering, tree mode, editing (the edited row stays rendered while scrolled away) and keyboard
navigation (a focus move scrolls its row into view) work over all rows; `aria-rowcount` /
`aria-rowindex` count every displayed row. Not combined with paging (`pageable` / server paging win).
For 2,000 rows × 8 columns the first render drops from ~1.1 s to ~30 ms.

QuickGrid is also faster without it: a filter keystroke or a sort no longer re-renders every
displayed cell (only the cells whose values changed run `getDisplayValueCallback` again).

- Select and Combobox: `onOpenChange({open})`. Across Select, Combobox, Autocomplete, DatePicker and TimePicker it now fires on every real change (user or `bind:open`) and never on the first render.

## Fixes

- **Select** `required` now blocks form submission (it was on a hidden input, which browsers don't
  validate); **Combobox** `multiple` `required` is enforced (no value picked → invalid).
- **QuickGrid** — a dropdown / date pick fired `onRowChange` twice (the second time with old = new
  value) when the editor's blur followed the commit, e.g. with `bind:invalidCells` in navigate mode.
- **QuickGrid** — after a valid edit the grid kept showing its own copy of the row, hiding changes you
  made to other fields in `onRowChange` (clearing a dependent field) and sending the stale values back
  in the next `draftRow`. The copy is now kept only while the row has an invalid cell.
- **QuickGrid** — rows edited / deleted on page 2, after sorting or in a collapsed tree hit the wrong
  row in the docs' pattern (`items[rowIndex] = …` used a screen position); events now carry
  `itemIndex`. Rows without `idMember` no longer share drafts and invalid markers across pages (they
  are keyed by row object, not position). The row toolbar keeps working when `items` is replaced
  immutably (`items = items.map(…)`), and the edited / focused cell follows its row through re-sorts.
- **QuickGrid** — `editorOptions.multiple` / `maxSelections` removed: declared but never implemented.
  For several values in one cell use `editor: "custom"` (see the task-tracker demo).
- **Select** — type-ahead with nothing selected lands on the first matching option (the first key press used to skip it).
- **Textarea** — `bind:value` now updates while typing (it was one-way).
- **Listbox** — a single-select `value` stays a string after a click, assigning `value` moves the
  selection, and `multi` sets the `multiple` attribute.
- **RadioGroup** — arrow-key selection updates `bind:value` and fires `onchange`; re-clicking the
  checked radio no longer fires `onchange`.
- **MenuButton** — enabled menu items no longer render a stray `disabled` attribute.
- **Calendar / DatePicker / Checkbox / Slider** — no longer touch `window`/`customElements` during server rendering; the locale default falls back to `en-US`.
- **Checkbox / Switch** — the auto-generated label id is stable between server and client (`$props.id()`).
- **Dialog / Panel** — Escape in an open dropdown, picker or menu inside them closes that popup first instead of closing the dialog and leaving the popup on screen.
- **DatePicker** — `minDate` / `maxDate` with a time of day no longer disable that whole day.
- **InputFile** — `formatInputFileSize` prints TB/PB instead of `undefined`.
- No more debug `console.log` output from the theme store and Listbox/Select selection.
- **Autocomplete** — a slow async search response can no longer overwrite newer results; search errors no longer surface as unhandled rejections; clicking inside another component's popup closes the dropdown.
- **QuickGrid** — arrowing through a cell editor's dropdown keeps the highlighted option in view.
- **QuickGrid** — in navigate mode a double-click on a dropdown cell no longer throws and leaves the cell without a working editor; the combobox editor shows the cell's text for a value that isn't among its options.
- **ToastContainer, QuickGrid, MultiSplitter, Tabs, Textarea/TextField** — no more timers, listeners or polling left running after unmount.
- **Tabs** — tabs added after the first render are measured for the indicator and scroll arrows.
- **CommandPalette / Toast** — z-index fallbacks corrected; toasts follow `--fluent-z-toast`.
- **Styles** — leftover Blazor CSS no longer restyles unrelated page markup (`.grid` tables, `div[part=label]`, `th.column-header`, `div[draggable]`, `a .stack-vertical`).
- **Checkbox** — the box no longer stays visually ticked after the value changes to unchecked.
- **CommandPalette** — opening it via `bind:open` focuses the search input and starts with an empty query.
- **Toast** — clicking an action link no longer adds `#` to the URL.
- **QuickGrid** — on touch devices an outside tap closes the row toolbar again.
- **AccordionItem** — a standalone item without `expanded` can be opened.
- **Select / Combobox** — a dropdown that starts open is no longer closed by SvelteKit's focus reset after navigation.
- **Select** — the trigger text, `onChange` option text and type-ahead use the option's `label` (not icon text inside the row).
- **Autocomplete** — closing the dropdown cancels an in-flight search (late results no longer reopen it); the highlighted row scrolls into view.
- **QuickGrid cell editor** — typing a letter on a closed select editor jumps to the match; the loading indicator no longer sticks after an aborted search; stale results can't overwrite the list; no timers left after unmount.
- **QuickGrid** — Escape while editing a cell inside a Dialog cancels the edit instead of closing the dialog; Escape in the Tabs overflow menu, CommandPalette, QuickGrid context menu and InputFile popover closes only that popup.
- **MenuButton** — items can be run from the keyboard (Enter / Space did nothing); arrows skip disabled items; ArrowDown / ArrowUp / Enter on the button open the menu with focus inside; Escape, Tab or running an item returns focus to the button.
- **ContextMenu** — keyboard: focus moves into the menu, arrows skip disabled items, ArrowRight / ArrowLeft open and leave submenus, Escape closes the deepest submenu first, focus returns to where it was.
- **Tabs** — in RTL the scroll buttons are on the right sides and scroll the right way, ArrowLeft moves to the next tab and the vertical indicator sits on the inline-end edge.
- **DatePicker / TimePicker** — a press on the popup's padding no longer closes it.
- **InputFile** — `expandOnDrag` no longer listens to page-wide drag events for selectors without the drop overlay.
- **MultiSplitter** — dragging a pane into its rail fires `onPaneCollapse` once instead of on every
  frame the pointer stays under the snap threshold.
- **TabPanel** — `defer` mounts the content on the first activation and keeps it mounted (it had no effect).
- **SiteSettings** — `children` render below the built-in settings (they were never rendered).
- **Listbox** — `height` caps the listbox and scrolls longer lists (it had no effect).
- **Grid** — `adaptiveRendering` works without `onBreakpointChange` (the grid width was only measured while that handler was set).
- **GridItem** — `hiddenWhen` follows window resizes (it was evaluated once).
- **Spacer** — `width` takes CSS lengths (`"1rem"`, `"10%"`); numbers and numeric strings stay px (`"1rem"` used to become `1rempx`).
- **Dialog** — `ariaLabel` / `ariaLabelledby` / `ariaDescribedby` reach `<fluent-dialog>` and its inner `role="dialog"` (they rendered as unknown `arialabel`-style attributes); `modal={false}` makes it non-modal (`aria-modal` was always `true`).
- **Accessibility — listboxes** — Select, Combobox and Autocomplete keep focus on the trigger / input and point `aria-activedescendant` at the highlighted option (unique option ids); Select works without an `id` (label, `aria-controls`); multi-select Select is keyboard operable; Autocomplete's input is the combobox over a real listbox, its label and `ariaLabel` name the input, and `required` sets `aria-required` and only invalidates the form while nothing is selected.
- **Accessibility — pickers** — DatePicker / TimePicker buttons announce a dialog popup (`aria-haspopup`, `aria-expanded`, `aria-controls`), the popup is a labelled `role="dialog"`; TimePicker columns are radio groups. Calendar is an APG grid with a roving tab stop and full keyboard (arrows, Home / End, PageUp / PageDown), `aria-selected`, `aria-current="date"`, `aria-disabled`; the next-period button is named after the next month.
- **Calendar** — `checkIfSelectedValueHasChanged` suppresses `onChange` for a re-pick of the selected date / month / year (it had no effect).
- **Accessibility — Tooltip** — `aria-describedby` on the anchor while shown; Escape hides it without closing an enclosing dialog.
- **Accessibility — clickable elements** — Badge, Label and CompositeBadge labels with click handlers are keyboard buttons; NavMenu rows (incl. NavGroup headers) activate on Enter / Space; closable tabs close on Delete; Paginator is a labelled `navigation` with a live status; CommandPalette rows are grouped options announced via `aria-activedescendant`.

- **Accessibility — chips** — every inline chip of a multi-select Autocomplete / Combobox can be removed
  from the keyboard (only the last one could, via Backspace on an empty input): ArrowLeft at the start
  of the input moves onto the chips, arrows / Home move between them, End returns to the input,
  Backspace / Delete remove the focused chip, Enter / Space remove it and return to the input. The ×
  buttons stay out of the Tab order. CompositeBadge's built-in × has an accessible name ("Dismiss").
- **QuickGrid** — in navigate mode, arrow keys pressed faster than a frame each move one cell (the
  second press used to repeat the move from the same cell); also with `virtualize`, where the target
  row still scrolls into view. Without `virtualize` the focused cell scrolls into view.
- **QuickGrid `virtualize`** — a focused cell (or row) scrolled out of the rendered rows keeps its
  focus (it fell to the page body): its row stays rendered outside the window, so the next arrow key
  continues from it. The row being edited is kept the same way (rows in between are no longer rendered).
- **MenuButton / ContextMenu in a Dialog** — keyboard focus can enter the menu (it was mouse-only there:
  the menu lived outside the dialog's focus trap). Menus and dropdowns / picker popups are now placed
  inside the enclosing dialog; DatePicker / TimePicker opened from the keyboard in a Dialog get focus too.
- **ContextMenu** — the keyboard ContextMenu key / Shift+F10 on another element closes an open menu;
  on the menu's own zone it re-opens at the new spot (re-opening while open didn't move it).
- **Focus rings** — InputFile buttons, the Toast close button, ValidationSummary links and Autocomplete's
  clear button use Fluent's focus stroke (black / white per theme, like Tabs and menus) instead of an
  accent outline; the Toast close ring shows for keyboard focus only.
- **Autocomplete** with `tagsPosition` top / bottom — `disabled` dims like the other fields, and
  `appearance="filled"` gets the filled hover and focus underline.
- **Accessibility: Combobox** — the "No results" / loading message is outside the `role="listbox"`
  (a listbox may only contain options); it looks the same.

## Internal

- Snippet props are typed `Snippet` / `Snippet<[...]>` instead of `any` (the internal `SlotType = any`
  alias is gone). Passing a string or component to a snippet prop is now a type error — it never
  rendered correctly anyway. Snippets with arguments: `AccordionItem.icon(isExpanded)`,
  `Calendar.day(day)`, `CommandPalette.item(item, selected)` / `empty(query)`,
  `TopNav.drawerContent(close)` / `menuToggleTemplate({open, toggle})`.
- FluentUI web components are registered once per component type (module script) instead of on
  every instance.
- Copy-pasted style blocks replaced by shared primitives (`_primitives.scss`): the field control box,
  popup surface, required indicator, focus ring, danger menu item and spin / pulse keyframes; labels of
  Select, Combobox, Autocomplete, DatePicker, TimePicker, NumberField and TextField render through one
  internal `FieldLabel`. Screenshot-compared before / after in light and dark: no visual change besides
  the fixes above.
