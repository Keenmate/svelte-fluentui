# svelte-fluentui 2.0.0-rc01 — Release Notes

**Released:** _unreleased_ · **Pre-release** (`npm install svelte-fluentui@rc`)

These notes cover the changes since **1.6.0-rc07**, the last version on npm.

This is a **major release: breaking, with no aliases.** Before the first public release the whole
API was revised for consistency: every callback prop is lowercase (`onfileselected`, not
`onFileSelected`), one name per concept across components (`open`, `value`, `multiple`, …), prop
values are lowercase / kebab-case, and shared logic moved into helpers. Code written for 1.x needs
updating: the old names are gone.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/KeenMate/svelte-fluentui/blob/prod/CHANGELOG.md) (section
2.0.0-rc01); this document is the upgrade guide and the highlights.

## Breaking changes

### Events and callbacks: camelCase, one `ctx` object

Events a component defines are now `on` + PascalCase and receive **one object** (`ctx`), so fields can
be added later without breaking you. Lowercase `on*` props are only real browser events, forwarded
untouched (they receive the native `Event`). Functions whose return value is used are named
`…Callback` (`before…Callback` can veto, `get…Callback` extracts a value).

```svelte
<!-- 1.x -->
<Switch onchange={(checked) => save(checked)} />
<!-- 2.0 -->
<Switch onChange={({checked}) => save(checked)} />
```

| Component | 1.x | 2.0 |
|---|---|---|
| Switch | `onchange(checked)` | `onChange({checked})` |
| Slider | `onchange(value)`, `oninput(value)` | `onChange({value})`; live value via `bind:value` |
| RadioGroup | `onchange(value)` | `onChange({value})` |
| Textarea | `oninput(value)`, `onchange(value)` | `onChange({value})` on commit; `oninput` / `onchange` are now the native events |

### Svelte 5.29 or newer

The library now uses `$props.id()` (Svelte 5.20) and attachments (`{@attach}`, Svelte 5.29). The
`svelte` peer dependency moved from `^5.0.0` to `^5.29.0`.

```sh
npm install svelte@^5.29
```

### Store types renamed (they were shadowed)

The toast and settings stores exported types with the same names as the `Toast` and `SiteSettings`
components, so `import type {Toast} from "svelte-fluentui"` gave you the component, not the store
type. Renamed:

| Before | After |
|---|---|
| `Toast` (store item type) | `ToastInstance` |
| `SiteSettings` (settings store value) | `SiteSettingsState` |

### Placeholder components removed

`Menu`, `MenuItem`, `Tree`, `TreeItem` and `ProgressBar` were exported but rendered an empty
FluentUI element with no props. They are gone. Use `MenuButton` / `ContextMenu` for menus; for a
tree, [`@keenmate/svelte-treeview`](https://www.npmjs.com/package/@keenmate/svelte-treeview).

## Behaviour changes

### MultiSplitter is content-height by default (as documented)

Leftover Blazor CSS forced `height: 100%` on every `MultiSplitter` and `overflow: hidden` on its
panes, overriding the component's own styles. With it removed, a splitter without a `height` prop
sizes to its tallest pane, and panes scroll (`overflow: auto`) instead of clipping. If a splitter
should fill a sized parent, say so:

```svelte
<div style="height: 400px">
	<MultiSplitter height="100%">…</MultiSplitter>
</div>
```

## Fixes

- **Textarea** — `bind:value` now updates while typing (it was one-way).
- **Listbox** — a single-select `value` stays a string after a click, assigning `value` moves the
  selection, and `multi` sets the `multiple` attribute.
- **RadioGroup** — arrow-key selection updates `bind:value` and fires `onchange`; re-clicking the
  checked radio no longer fires `onchange`.
- **MenuButton** — enabled menu items no longer render a stray `disabled` attribute.
- **Calendar / DatePicker / Checkbox / Slider** — no longer touch `window`/`customElements` during server rendering; the locale default falls back to `en-US`.
- **Checkbox / Switch** — the auto-generated label id is stable between server and client (`$props.id()`).
- **Dialog / Panel** — Escape in an open dropdown, picker or menu inside them closes that popup first instead of closing the dialog and leaving the popup on screen.
- **DatePicker** — `minDate` / `maxDate` with a time of day no longer disable that whole day.
- **InputFile** — `formatInputFileSize` prints TB/PB instead of `undefined`.
- No more debug `console.log` output from the theme store and Listbox/Select selection.
- **Autocomplete** — a slow async search response can no longer overwrite newer results; search errors no longer surface as unhandled rejections; clicking inside another component's popup closes the dropdown.
- **QuickGrid** — arrowing through a cell editor's dropdown keeps the highlighted option in view.
- **ToastContainer, QuickGrid, MultiSplitter, Tabs, Textarea/TextField** — no more timers, listeners or polling left running after unmount.
- **Tabs** — tabs added after the first render are measured for the indicator and scroll arrows.
- **CommandPalette / Toast** — z-index fallbacks corrected; toasts follow `--fluent-z-toast`.
- **Styles** — leftover Blazor CSS no longer restyles unrelated page markup (`.grid` tables, `div[part=label]`, `th.column-header`, `div[draggable]`, `a .stack-vertical`).

## Internal

- Snippet props are typed `Snippet` / `Snippet<[...]>` instead of `any` (the internal `SlotType = any`
  alias is gone). Passing a string or component to a snippet prop is now a type error — it never
  rendered correctly anyway. Snippets with arguments: `AccordionItem.icon(isExpanded)`,
  `Calendar.day(day)`, `CommandPalette.item(item, selected)` / `empty(query)`,
  `TopNav.drawerContent(close)` / `menuToggleTemplate({open, toggle})`.
- FluentUI web components are registered once per component type (module script) instead of on
  every instance.
